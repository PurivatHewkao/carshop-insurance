## วิธีอ่านผล

- **ผ่าน** หมายถึงผลตรงกับเกณฑ์ของเคสนั้น เช่น เปิดหน้าแล้วแสดงหัวข้อ หรือ API บันทึกสถานะที่อ่านกลับได้
- **ไม่ผ่าน** หมายถึงพบพฤติกรรมขัดกับเกณฑ์ทางธุรกิจหรือการส่งมอบ
- **ขาด** หมายถึงหน้ายังเป็นโหมดสาธิต/placeholder หรือยังไม่มีโค้ดเชื่อมข้อมูลจริง
- **ยังไม่ยืนยัน** หมายถึงยังไม่มีผลทดสอบพอจะตัดสิน
- ชุด Route Smoke ตรวจ URL และหัวข้อที่แสดง รวมถึงหน้าปฏิเสธสิทธิ์ คุณภาพข้อมูล การทำรายการ และสิทธิ์ของ backend มีเกณฑ์แยกด้านล่าง การตรวจสิทธิ์ backend ที่ระบุว่า **ตรวจโค้ด** มาจากการอ่านการผูก middleware กับ route จริง
- ฐานจำลองลง migration ครบตามที่แต่ละ feature ใช้ สภาพแวดล้อมสำหรับ production, Node 24 และการทดสอบขนาดจอหลายแบบยังไม่ได้รับการยืนยันในรอบนี้

## ตรวจซ้ำก่อนเซ็นรับ

| ลำดับ | เจ้าของ | เกณฑ์ตรวจรับ |
| --- | --- | --- |
| 1 | โจเซฟ + กร/เฟียร์/ดิว | Business API ที่จำกัดสิทธิ์ตอบ 401 เมื่อไม่มี session และ 403 เมื่อบทบาทไม่มีสิทธิ์. ผู้ใช้เห็นและแก้ได้เฉพาะข้อมูลที่ได้รับอนุญาต. หลัง logout หรือระงับบัญชี บริการปลายทางปฏิเสธ session เดิม |
| 2 | เฟียร์ + กร | ผ่านเส้นทางบนเว็บตั้งแต่ Customer นัด → Manager มอบหมาย → Seller ปิดงาน → Seller สร้าง Order → Manager อนุมัติ. ต้องเห็นสถานะเดียวกันจากทุกบัญชีหลัง reload และยืนยันกรณีปฏิเสธ/ยกเลิก |
| 3 | ดิว + เฟียร์ + อั้ม | ออกบิลจาก Order ที่อนุมัติผ่านเว็บ, จ่ายจำลอง, ดูสถานะและประวัติจาก Payment API, ป้องกันจ่ายซ้ำ, คืนเงินและตรวจสถานะ Order/สต็อกหลังคืนครบ. ใช้บัญชีปฏิบัติงานตามสิทธิ์ที่ทีมอนุมัติ |
| 4 | กร + โจเซฟ + อั้ม | Admin หรือ Stock ตามสิทธิ์ที่ตกลงปรับสต็อกแล้ว Catalog สาธารณะสะท้อนผล. Admin จัดการรถและโปรโมชันได้ และ UI แสดง loading/empty/error ตามกรณี |
| 5 | อั้ม + ทุกคน | รัน Build, Lint, Smoke และชุด UAT ซ้ำบน Node 24 ใน staging. Dashboard และ CSV ต้องตรงกับข้อมูลต้นทาง หากอยู่ในขอบเขตส่งมอบ. ตกลงเจ้าของและวันส่งสำหรับหน้าที่เหลือ พร้อมแนบหลักฐานและให้ผู้แทนแต่ละบทบาทเซ็นรับ |

## ผลเครื่องมือและข้อจำกัด

- `npm run build` ผ่าน มีคำเตือน JS chunk 632.77 kB หลัง minify (174.65 kB gzip)
- `npm run lint` ไม่ผ่าน 6 จุด คือ Catalog 2 จุด (`CarPhoto.jsx:22`, `CarsPage.jsx:22`) และ `db schema/02_mongodb_schema.js` 4 จุดจาก global ของ Mongosh
- `scripts/smoke.mjs` หยุดใน Identity ที่ assertion ของ JSON error (HTTP 400 ผ่าน แต่ code หาย) จึงไม่สรุป Smoke ชุดนี้ว่าผ่านทั้งระบบ. Integrated Smoke แยกตรวจ health, CORS และ 404 ครบห้าบริการ
- ชุด Identity ที่ใช้ config เดิมติด DNS ของ MySQL จากนั้นผ่านบน MySQL ชั่วคราว. ชุด Payment ถูกเรียกด้วยชื่อไฟล์เทสต์ตรง เนื่องจาก wildcard ของคำสั่ง package test บน Node 20/Windows หาไฟล์ไม่เจอ
- รายงานใช้บัญชีจำลอง ฐานชั่วคราว และ browser runner บน localhost. การตรวจโดยผู้ใช้งานจริง, staging/production, browser อื่น และการทดสอบข้อมูลขนาดจริงยังรอดำเนินการ
